# 桌面工作台与用户定稿

PixForge 提供 Windows C++/Win32 原生桌面，连接独立核心，以 PixiEditor 的工作区布局为主要参考，并借鉴 Pixelorama 的像素与动画交互。用户在当前对话提出意见，AI 通过同一份工程继续修改；用户在窗口查看结果，讨论通过后导出正式 PNG 或形状数据。

PixForge 2.3 的“资源”菜单提供 Minecraft 目标配置、来源优先级、引用诊断和 Forge 1.20.1 版本化导出，见 [目标与资源](minecraft-assets.md)。配置窗口使用独立草稿，校验后一次应用并可撤销；取消不改变工程。`pixelforge ui --runtime <会话> minecraft-editor ...` 可查看、编辑草稿和应用，不能通过该入口批准或导出。软件自带 Minecraft 资源示例使用合成工程，不修改已有作品。

## 打开软件

完整软件包独立于 skill 安装。直接双击软件目录的 `PixForgeNative.exe` 或 `打开PixForge.cmd` 即可启动；保留相邻 `backend` 和 `application.json`。软件不读取或寻找 skill 文件。用户已有软件时，先按 [连接说明](connection.md) 指定位置并运行 `doctor`。

```powershell
python <skill-base-dir>/scripts/pixforge_client.py --app <软件目录> gui --workspace <任务项目> --runtime <会话目录>
```

`gui` 后可加 `.pixforge`、旧会话 JSON、PNG 或 `.px` 路径。CLI/MCP 与窗口指定相同 runtime，读取同一工程和历史；不同 runtime 是隔离工程，不能以新建空会话代替用户眼前的工程。关闭窗口后软件核心继续运行。软件运行环境和首次依赖准备由软件自身管理。


## 编辑工作区

“文件 → 新建工程”（Ctrl+N）先选择模型：六面独立、六面共用、导入模型 JSON，或明确选择纯像素画布。窗口展示所选模型的 UV 布局与几何线框；内置方块调整每面像素尺寸后自动得到匹配图集，导入模型按自身 UV 组织分区并允许调整纹理分辨率。改变设置后须更新预览，创建按钮才重新启用；取消不会改变当前工程。点击创建后，先按现有流程处理旧工程保存，再一次性建立新工程。空白纹理只显示模型几何线框，画出像素后显示实际纹理；线框与分区均不会进入图层或 PNG。

工作区采用深色表面和统一图标。顶部是文件、编辑、图层、动画与视图菜单，以及画笔大小、不透明度、镜像和保存/导出操作；左侧是像素工具，中央是最近邻画布，右侧是颜色、导航和图层，底部是帧时间轴。右侧面板与时间轴可在“视图”菜单隐藏或重新显示，分隔条可调整尺寸；窄窗口的颜色面板支持滚动。

布局以 [PixiEditor](https://github.com/PixiEditor/PixiEditor)（LGPL-3.0）为主要视觉范本，像素、帧缩略图与时序交互参考 [Pixelorama](https://github.com/Orama-Interactive/Pixelorama)（MIT）。C++ 前端使用 Win32、GDI/GDI+ 与 OpenGL；界面与图标均独立实现，未复制这两个项目的源码、图标、品牌或素材。这些参考不改变 PixForge 原有源码的许可状态。

### 绘制与图层

C++ 工具栏第一项为平移，启动、打开或新建工程后默认选择平移 H；需要绘制时再主动选择画笔等绘图工具，避免进入工程后意外落笔。

载入带 UV 的模型后，C++ 画布默认显示真实面域边界；顶部“面域”滑动开关可关闭。画布内不显示文字标签，避免遮挡像素。右侧“面域”页签列出区域编号、画布像素范围、部件名称和局部面方向；共用区域显示全部相关面。悬停画布查看该像素被哪些面采样，Ctrl+单击固定或解除，亦可点击面域列表固定某一区域。列表支持滚轮；动画帧与平铺使用同一帧内映射。UV 的部分重叠会返回多个区域，旋转和镜像保留在对应面记录中。所有辅助线和固定操作只改变视图，不进入 PNG、图层或撤销历史。

像素画布是纹理图集，不具有固定的模型面数。“模型与形状”读取当前嵌入模型的部件、几何面和 UV；六面立方体可以六面共用同一区域，也可以各面使用不同区域。替换模型同步替换其 UV、面域查询及预览网格，保留已有像素；软件不推断旧图集各图块的含义或自动重排。新模型与旧图集布局不一致时，需要配套纹理或明确重新映射 UV。打开普通 PNG 会清空旧模型绑定，不能从颜色推断几何。

左键绘制，右键或 Alt+左键采样当前合成颜色。快捷键为画笔 B、橡皮 E、填充 G、吸管 I、直线 L、矩形 U、椭圆 O、平移 H、矩形选区 M、移动 V（选区和移动为 C++ 前端新增）；形状工具可选择轮廓或填充。画笔大小与不透明度影响本轮笔画，RGBA 输入使用 `#RRGGBBAA`。颜色环、饱和度/明度方形区、透明度滑条和调色板共同编辑前景色，不改写已有像素。

C++ 前端用 M 拖动矩形选区，虚线显示边界；后续绘制仅影响选区。Ctrl+A 选中当前帧，Ctrl+D 或 Esc 取消选区。V 在当前图层内移动选区，方向键移动一像素，Shift+方向键移动十像素；拖动中 Esc 恢复原像素和选区。Ctrl+C/Ctrl+X 复制/剪切当前图层，Ctrl+V 粘贴到选区左上角或当前帧原点，Delete 清空选区；粘贴超出当前帧的部分会裁切。PixForge 窗口之间的剪贴板保留精确 RGBA，同时发布 Windows DIBV5 图像，支持接收常见 PNG 和 24/32 位 DIB。剪切、删除、移动和粘贴均可撤销，切换帧、图层或工程会清除选区。输入框中的 Ctrl+A/C/X/V 仍处理文字。

滚轮围绕指针缩放，空格拖动或中键拖动画布；平移时显示张手光标，拖动中为抓手，松开后恢复，Ctrl+0 适应窗口，Ctrl+1 原尺寸。网格、平铺、洋葱皮、镜像、形状填充、循环播放、模型与形状叠加、图层显示中的开关项统一使用滑动开关：开启时紫色轨道、滑块在右，关闭时灰色轨道、滑块在左；轨道为 28 × 16 的紧凑尺寸，整组标签仍可点击，状态名称保留在辅助信息与命令接口中；点击标签或开关均可切换，快捷键与命令接口同步状态。鼠标点击不绘制外围白框，Tab 键导航时使用细主题色焦点提示。像素网格、透明棋盘背景、3×3 平铺和洋葱皮都属于视图；显示工具、缩放、切帧与播放不使当前确认失效。

手动笔画限制在当前源帧内；水平 X 与垂直 Y 镜像也以当前帧为边界，不跨图集绘制。直线、矩形与椭圆在拖动期间预演，松开后提交一条共享历史，Esc 取消。人的笔画尚未结束时，AI 写入得到 BUSY，需等用户完成后重读状态。

图层面板显示当前源帧的缩略图，支持新增、复制、重命名、显示/隐藏、上下移动和删除；双击名称重命名。图层最多 16 层，至少保留一层。选择图层只切换编辑目标，改变像素、层顺序或显示状态才会重新进入待确认状态。Ctrl+Z、Ctrl+Y、Ctrl+Shift+Z 与工具栏撤销/重做使用同一份人机共享历史；输入框保留文本自己的键盘撤销。

### 帧时间轴

底部缩略图按实际播放步骤显示，每步保留源帧索引和毫秒时长。点击缩略图切换步骤，播放/暂停、前后步与循环控制直接可见。时长输入支持小数，未修改输入时不会将来源定义中的高精度数值重新取整。右键步骤可调整播放先后；顺序可以重复引用同一源帧，不把物理图集排列等同于播放顺序。

新增空白帧、复制与删除源帧同时处理所有图层和播放索引，保留已有步骤的时长，并可一次撤销。删除源帧会删除引用该源帧的全部播放步骤。为避免丢掉 UV 矩形外的像素，这些操作只接受完整规则图集；部分或重叠矩形需先决定布局。重排后的图集每边仍不超过 4096 像素，总源帧不超过 4096，播放步骤不超过 10000。

“动画 → 按帧尺寸切分图集”支持横向、纵向及二维规则图集；“载入显式播放定义”使用 [动画协议](animation-review.md)。分帧默认 100ms 仅是编辑器预览值，不代表 Minecraft tick 或生产元数据。预览、洋葱皮与导航都读取内存里的原生像素，不要求先导出 PNG。

### 场景动画

“模型与形状”面板下部可载入部件/粒子场景 JSON，或清除场景。部件旋转、位移、缩放与固定种子粒子在 C++ 中实时采样，和材质共用毫秒时钟；一张静态贴图也能播放完整场景。底部时间条可连续定位，暂停/恢复保留当前时间。场景随工程保存和撤销，旧确认在内容改变后失效。`ui_set.time_ms` 与 `ui scene-sample` 提供同一视图的接口；参数和接入限制见 [场景动画](scene-animation.md)。

### 工程保存

三维预览中，滚轮向上放大、向下缩小，范围为 10%–800%，不改变水平或垂直角度；左键拖动旋转，水平拖动方向与模型跟随鼠标的方向一致，上下拖动沿用原有行为。“模型与形状”页中的模型、粒子与形状线框同步缩放。该缩放独立于像素画布，可通过 `ui_set.scene_zoom` 查询或设置，不写入作品与撤销历史。

中央“模型与形状”页提供基础、碰撞覆盖和选中覆盖编辑，默认两种形状继承基础。支持盒列表、六轴坐标、新增/删除、继承/独立覆盖、模型载入、线框开关和视角调整。底部时间轴同步模型纹理；可选 JSON 或 Forge 1.20.1 Java 导出。数据、游戏接入限制及测试方式见 [形状说明](shapes.md)。

保存工程始终可用，保留图层、原生 RGBA、调色板、时序和当前确认记录。`.pixforge` 与旧 Canvas JSON 兼容，旧 CLI 仍能读取像素层；旧 CLI 不管理桌面附加信息。切换工程前可以保存；未保存工程另外保留 runtime 恢复稿，可从“文件 → 打开恢复稿”找回。打开 PNG、脚本或旧项目本身不授权重绘、补齐或动画设计，也不改写原文件。

讨论继续在当前对话中进行，脚本执行与预演由下面的 AI 接口处理；已有工程的讨论记录仍兼容读取和保存。共享绘图批次中的 `new/load/render/save/undo/redo` 会被拒绝，使用专用创建、打开、保存、导出与历史操作；离线 run 保留完整协议。

## AI 与桌面使用同一工程

形状页默认使用“保守重建原模型”，误差上限与目标箱数可调整；无损整理作为可选项。核心、CLI、MCP 与桌面的默认策略和验证方式见 [形状说明](shapes.md#构建和减少分箱)。

AI 通过 CLI/MCP 调用独立核心，不操作鼠标键盘。窗口打开与否不改变绘制、动画预览、对话确认或导出能力；用户需要查看和手动修改时应打开窗口。核心会话发现、当前版本令牌、动画 HTML 预览、真实用户确认、导出与恢复方式统一见 [独立会话与定稿](session.md)。不要在磁盘上改写正在使用的工程来代替共享接口。

用户自行点击“确认并导出”时，先选择路径再核对当前版本；取消选择不产生确认，选择期间作品改变会拒绝此次操作。已有有效确认时直接导出。GUI 与对话批准使用同一内容绑定检查，不要求用户额外重复点击。

## 原生构建与性能路径

软件的源码、构建入口与测试均在独立软件源码包中，集合维护位置为 `apps/pixforge`，不放在 skill 内。skill 只用公开 `gui`、`ui`、`session` 和 MCP 接口；无需构建软件或安装桌面依赖。

原生前端内不加载 Python 或 Qt。像素画布由 C++ 最近邻绘制，笔画只传变化区域到独立核心；工程和共享历史仍由 Python/Pillow 管理。OpenGL 可用时保持几何缓存和图集纹理，模型拖动只更新相机，不逐次请求核心或重传纹理；没有硬件加速时使用异步 C++ 软件渲染并显示已完成的帧。像素与形状两页固定使用透明棋盘背景，不再提供背景切换选项。`PIXFORGE_DISABLE_GPU=1` 可检查软件路径。GPU 帧率与离线软件渲染基准单独报告，不能把局部基准当作整个软件的倍数。

## 维护与验证

连接检查使用 `doctor`，然后在明确的隔离 runtime 通过公开接口检查状态、操作、预览、撤销和恢复。本 skill 不运行或导入软件内部实现。隔离素材不能作为用户作品的批准或游戏内证据。截图使用软件公开 `ui capture` / MCP `desktop_capture`，仅渲染本程序客户区。

## Forge 模组接入

软件 2.4 的目标窗口增加 Forge 接入 JSON 和“按当前工程生成接入草稿”，绑定部件 / 粒子场景。普通绑定设空，避免同时生成静态外观。校验后可用“查看生成代码与接线说明（只读）”检查 Java、实际数据定义及两种导出契约，不会批准或写出正式资源。

“资源”菜单另有确认并导出 Forge 模组接入包、确认并导出可构建示例模组。前者不带 @Mod 入口和构建文件，后者提供独立示例注册与 ForgeGradle 构建；均通过当前证据、真实确认和版本校验。独立示例启动器使用自有合成工程。运行时目标工程 / 历史使用 v3 格式，需要软件 2.4+，已有工程不自动转换。具体结构状态、服务端同步和客户端执行器接线见 [Forge 接入说明](forge-runtime.md)。
