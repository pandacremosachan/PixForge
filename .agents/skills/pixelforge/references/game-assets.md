# Minecraft 资源类型与动态材质

先确认项目实际 Minecraft/加载器版本、资源命名空间、资源源目录、datagen 和渲染机制。Forge、Fabric、NeoForge、数据包和资源包的接入方式由当前项目决定，不默认 CTNH、GregTech、16×16 或某种渲染扩展。

软件提供 [目标版本、资源引用与版本化导出](minecraft-assets.md) 流程，第一项适配器为 Forge 1.20.1。生产交付时用软件公开接口保存实际目标和来源，检查父模型、纹理别名、状态/物品引用、覆盖与元数据，再使用与当前证据和用户确认一致的指纹导出。读取检查结果及未支持项，不把其他版本标成已适配。

## 按资源选择方法

- **普通方块与地表**：先定纹理尺度、材质特征和相邻面方向，检查至少 3×3 平铺。自然纹理允许不对称；机械框、槽和规则晶棱按设计选择对称关系。
- **物品、工具和材料粉末**：读 [小尺寸图标与工具](icons.md)，轮廓在物品栏缩放下可读，透明背景正确；相关加工阶段保持可识别的形状/色系变化。先查已有材料图标或自动生成体系，能复用时不单独画一批覆盖它。
- **GUI 图标、按钮、槽位、HUD**：与所在界面的像素密度和字体匹配，列原始尺寸与实际绘制尺寸。复用现有 atlas、九宫格或 UV 规则，避免硬编码成一个版本的布局。
- **透明玻璃、流体和发光块**：花纹、透视窗口和 alpha 有明确分工。PNG alpha 只是输入；项目代码的 cutout/translucent 等渲染层、模型面和排序还会影响可见性。发光纹理不等于发光等级或真实光照；按项目现有机制接入。
- **坐标渐变与着色**：若颜色由 tint、着色器或世界坐标决定，沿用该颜色来源，图片负责其真正承担的明暗/细节。局部贴图不能冒充跨多方块连续的颜色场。

GUI 状态、像素边缘、透明背景与实际绘制尺寸见 [设计决策与视觉验收](design-review.md)。按项目实际机制核对资源路径/namespace、模型及 tint 引用、动画侧文件与覆盖优先级；文件存在或构建成功不证明目标实例加载了该资源。未授权部署时仍可完成源资源引用检查。

## 动画先确定机制与语义

动画可由材质逐帧、模型部件变换、客户端粒子和着色器等不同机制组成。根据用途先区分图案运动、几何运动和离开模型的效果，再设计时序；PixForge 当前原生支持前三种的组合，着色器另需项目适配。部件/粒子的协议、默认 Forge 1.20.1 目标及真实预览见 [场景动画](scene-animation.md)。

说明动的是哪个部件、发射器或纹理、流向与图案切线的关系、周期、速度节奏、亮度是否变化和停止/异常状态。已有用户说明优先。“呼吸”可能指速度或明暗，不把某个项目曾采用的定义设为通用规则。

流动沿设计方向推进相位，周期采样在空间和时间上闭合，别每帧重新随机生成噪声。缓慢加减速可用单调相位，例如 `p(t)=t/T-a·sin(2πt/T)/(2π)`、`0≤a<1`，速度会变化但不会倒流；该模型只是选择之一。位移必须配合纹理方向和周期，不把水平平移强套在斜纹上。

读取当前项目使用的动画元数据或动态渲染代码，确认帧尺寸、排列、播放顺序、时长和插值。需要 `.mcmeta`、atlas 或自定义动画定义时按项目实际格式制作，不统一假定垂直正方形帧。输出资源时沿用 datagen 边界和命名空间。

查看全部原生帧，并按真实顺序和时长播放足够的循环，确认运动方向、相位接续和停顿意图。帧间轮廓、基线、结构与颜色变化须服务运动；不每帧自动居中，也不把正常位移当作错位。首尾帧之间的接续要与其他相邻帧一起判断，不能强制复制首帧到末帧造成停顿。

## 检查

普通 PNG 使用软件公开 `preview` 的尺寸、透明度、可选对称和平铺检查。针对玻璃查看透明、半透明、不透明像素比例，不能仅凭某一个透明像素认定整体可透视。

连接纹理、管线和复合模型先列出实际状态：孤立、直线、弯角、分支、接口/端盖，以及各轴朝向。核对当前版本的模型、blockstate、连接条件、UV 区域和旋转；长直线须由真实中心件、连接臂和端盖组合预览。整张 PNG 的平铺通过不能证明这些模型连续，无条件渲染的中心面也可能打断连接臂上的定向条纹。

离线模型预览应遵循目标加载器的面顶点/UV 顺序、旋转、uvlock、偏移和方向明暗，优先调用项目实际烘焙实现。手绘展开图或近似渲染应说明范围，不能称作游戏内验证；未确认这些规则时，先交付真实 UV 裁片及资源状态检查，不编造“实际效果”。同一家族在相同光照与朝向下并排比较，确认类别色在连接后仍容易区分。没有额外授权时按项目规则保持离线，不为材质验收自动启动游戏。

UV 单位换算、动画帧偏移、共享纹理编辑范围与模型状态矩阵见 [Blockbench 方法整合](upstream-workflows.md#blockbench从-uv-和模型状态决定检查范围)。编辑器的实时模型预览有助于检查方向，但项目扩展模型、状态规则与最终渲染仍以项目实际实现为准。

已确认是垂直帧条时，可以按每帧检查：

```powershell
python <skill-base-dir>/scripts/pixforge_client.py preview animation.png --frame-height 32 --expect-size 32 32 --tile --preview animation-review.png
```

`--expect-size` 此时指每帧尺寸；同时使用 `--region` 时指每帧所选区域的尺寸。报告检查每帧的透明度、对称/接缝约束和可选色簇，并给相邻帧变化和末帧到首帧的变化；首尾帧不必相同，重复同一帧可能造成停顿。变化大小不是动效美观或流向正确的判定。检查器按顺序帧分析，不解释播放元数据中的重排和不等时长；必须另行核对。

预览包含首帧的原尺寸/放大/平铺和全部帧的分行 contact sheet，报告列出其中的帧索引；按需加入深浅背景和指定绘制尺寸。contact sheet 没有播放时长，检查器也不解释元数据重排；使用 [动画播放器](animation-review.md) 从项目元数据转换的显式播放定义查看真实顺序/时长、循环及洋葱皮。插值或动态 UV 需要对应的项目渲染适配器，不能把静态帧播放器当作等价实现。输入 APNG 不等于 Minecraft 动画条，检查器会拒绝而不静默取首帧。最终交付说明已经验证的是素材约束、资源引用、声明时序还是游戏内效果，不能互相替代。
