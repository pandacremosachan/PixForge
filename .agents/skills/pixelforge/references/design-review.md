# 设计决策与视觉验收

适用于新素材、风格修改和成套资源审查。先从用户要求、项目规则和真实参考确定设计目标，能够推断的直接决定；不把这份指引变成逐项审批表。

## 从参考中提取可执行的风格

查看目标图片及相邻素材，区分用户已经认可的特征与本轮要改的问题。提取像素密度、轮廓线宽、明暗跨度、光源、材料处理、细节密度和类别色，不只说“工业风”“复古风”。功能、材料、类别和使用距离共同决定图案；同为金属，工具刃口、箱体和粗糙铸件可以采用不同表现。

先用大形验证一个代表性部件，再扩展家族。风格或布局仍不明确时，在草稿中比较有实质差异的轮廓、主部件比例或色块组织；不为每次例行绘制强制生成固定数量的方案。原尺寸下选定可读的大形后，再补细节与变化。

修改既有 PNG 时，从源图提取原生 RGBA，用 `patch` 等方式建立准确基底，先核对草稿导出的可见像素等价，再修改目标部件；不凭放大图近似重绘全部像素。`load` 只载入 PixForge 会话 JSON。无关资源保留原文件，已认可部分按本轮范围核对像素差异；PNG 重新编码的文件字节差异与可见像素差异分别判断。

局部修改可把已认可部分列入原生保护蒙版，用 `--preserve-mask` 对照基线核对完整源图；成套配色有明确约束时用 `--palette` 检查实际合成 RGBA。结构母版、颜色角色和参数组织见 [上游方法整合](upstream-workflows.md)，按实际任务选择，简单手绘不需要完整节点流程。

## 构图、颜色和像素组织

- **轮廓与留白**：检查主部件、负形和部件间距。细线、缺口和尖角是否在实际尺寸下仍能辨认？避免两个无关边缘恰好相切、只差一个难辨像素，或轮廓被高光切断。按布局确定基线和视觉重心；几何居中、可见像素居中与视觉平衡可以不同，不自动把所有物品移到画布中央。
- **明暗主次**：检查主体、结构阴影、材料高光和类别标记的强弱。需要时用灰度辅助观察亮度分组，再回到彩色判断；灰度通过不是彩色可读的充分条件。不要让每条边、每枚触点都同样明亮，把主部件淹没。
- **颜色分工**：相邻颜色应有实际作用，过近的色阶在原尺寸下可能失效。结合明度、色相与饱和度区分类别，成套素材还可用形状或结构提示用途/等级，不只靠微小色差。tint、状态着色与贴图底色分工明确，避免重复染色。
- **边缘节奏**：斜线、曲线与轮廓转折采用符合形状的像素阶梯，修正无意的突刺、凹点和重复双宽线。检查沿轮廓平行堆叠的色带是否让边缘发糊；不把每个弧线或自然破口强行改成同一种步长。
- **色簇与细节**：先组织面、棱、槽和有意义的连续色簇，再增加指示灯或纹理。孤立像素、抖动和颗粒可以有意保留，须在原尺寸下发挥作用。抖动应服务色阶过渡或材料，不能随机撒点来填空；平滑、粗糙、像素抗锯齿等处理按参考风格选择。
- **光照与材料**：同一家族保持光源逻辑，局部高光的位置随面向和结构变化。贴图预烘焙明暗、模型方向阴影、tint 与发光机制分别核对，避免叠加后过暗、过曝或材料混淆。对称结构不要求所有光照颜色对称，按 [对称范围与变换](symmetry.md) 选择对象。

## 使用环境中的检查

看最终导出的原生 PNG、最近邻放大，以及资源实际绘制尺寸。真实用途可能还包括物品栏、手持模型、GUI 状态、世界中远近不同的面和重复铺设。根据任务选择相关场景，不为无关素材强行补齐所有场景。

透明精灵至少结合实际背景判断边缘；棋盘格便于看 alpha，但深色、浅色或游戏背景能暴露消失的轮廓、浅色毛边和半透明脏边。透明度约束按渲染机制确定：有意半透明、像素抗锯齿和纯硬边透明不是同一种设计。`alpha` 检查比较透明度数值；只检查可见轮廓时用 `silhouette`，并明确可见性阈值。

物品与动画检查可见范围、与画布边缘的关系和帧间基线。接触边缘可能是平铺或满幅设计，也可能是被裁切；包围盒只是证据，不能自动认定要留白或平移。动画中包围盒中心移动也可能是运动本身，不把逐帧强行居中当修复。

图集/UV 材质检查实际采样区域、朝向、过滤、缩小时的 mipmap 行为和邻区串色；按项目现有机制处理保护边、纹理扩展或采样边界，不能随意往 atlas 加边导致 UV 错位，也不能为掩盖问题擅改全局过滤设置。辅助预览的最近邻缩放不证明目标渲染器使用相同过滤。

动画在全部帧 contact sheet 之外，使用 [显式顺序与时长的播放器](animation-review.md) 检查真实节奏；插值、tint、动态 UV 和游戏材质处理交给项目真实渲染适配器。播放定义的来源与单位必须可核对。

成套资源在相同背景、光照和绘制尺寸下并排看，检查等级、功能和状态区分。GUI 素材按项目存在的普通、悬停、按下、禁用、选中等状态检查，符号位置和语义须连续；字符、数字与槽位图案不要互相挤占。平铺与连接状态见 [材质验收](textures.md) 和 [Minecraft 资源接入](game-assets.md)。

## 发现问题后优先改什么

| 观察到的问题 | 优先修正方向 |
|---|---|
| 原尺寸看不清主体 | 调整轮廓、主部件面积、留白或主次对比，再决定细节是否保留。 |
| 放大精细，实际尺寸杂乱 | 合并色簇，删掉重复装饰或过近色阶，保留用途和材料线索。 |
| 材料不像目标材料 | 核对面结构、高光连续性、粗糙度与参考，避免只换颜色或堆亮点。 |
| 成套类别难区分 | 同时检查类别色、形状/部件变化及真实 tint，保留用户已认可的映射。 |
| 深浅背景下轮廓丢失 | 核对轮廓颜色、半透明边缘和实际渲染层，不靠额外展示光晕遮盖。 |
| 平铺/连接出现条带或断裂 | 核对重复大形、UV、旋转和模型状态，再改相应面或连接件。 |
| 动画跳动、闪烁或停顿 | 看全部帧与实际播放顺序/时长，核对基线、相位、亮度和循环接续。 |

修改后回看最终导出；涉及整体风格或家族规则时同时复核受影响成员。优先解决实际观察到的问题，不为了降低某个统计值反复重画已认可的素材。

## 验收结论需要对应证据

交付说明设计目标、改动、查看过的使用场景，以及适用约束的结果。单张简单图不必制造额外报告；复杂家族、局部规则或动态资源可保存对照图与检查记录，便于复查。

分别说明视觉判断、PNG 像素约束、资源引用/状态和渲染效果的检查范围。没有声明约束时，检查器退出码 0 只表示读取和分析成功；有约束时也不能代替视觉判断。抽帧图不能证明所有帧和运动语义，构建成功不能证明游戏加载了正确覆盖资源。若当前授权只允许离线，就报告已完成的离线证据和剩余渲染范围，不自动启动游戏或新增审批。
