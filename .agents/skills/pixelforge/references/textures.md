# 方块与可平铺材质

适用于 Minecraft、GregTech 等方块材质和地面、墙面、晶体表面。单张角色或海报不必采用平铺要求。

## 绘制前的判断

先从用户要求和项目资源确认以下约束，能够推断的直接确定，不为例行设计逐项追问：

| 项目 | 需要确定的内容 |
|---|---|
| 原生尺寸 | 跟随已有资源，如 16×16 或 32×32；放大图只是预览。动画条带应逐帧检查。 |
| 对称对象与范围 | 是整张图、局部部件、部件之间的对应，还是轮廓/结构层/成品颜色？定向光照或磨损可以使对称结构上的颜色不对称。 |
| 对称方式 | 按部件选择水平/竖直/斜轴镜像、中心对称、旋转或复合变换；轴线和中心未必位于整图中央。 |
| 重复方向 | 横向、纵向或双向；模型是否会随机旋转纹理，是否需要端面、侧面分别绘制。 |
| 风格锚点 | 查看同项目相邻素材，匹配像素尺度、配色、对比度与细节密度。 |

自然砂石以连续、自然的平铺为目标；不要为了提高对称百分比，把颗粒强行折叠成花纹。规则晶面、机械边框则先建立几何秩序，再添加允许的变化。

参考风格、配色主次、像素边缘与使用尺寸见 [设计决策与视觉验收](design-review.md)。缩小后的条带、重复大斑和对比失衡也需查看，不能仅通过对称与色簇统计判定材质完成。

具体范围、偏移轴线与局部坐标见 [对称范围与变换](symmetry.md)。分别检查端盖、接缝、镶嵌结构等设计选定的部分；一张材质可以含多个不同的局部对称结构，整图仍然不对称。

## 组织形状和颜色

- 先用少量色块建立材质结构，再加颗粒、裂纹或高光。像素应形成可读的小色簇，避免无目的的孤立噪点。
- 区分底色、结构阴影和高光的作用。不要只靠逐级变亮的同心轮廓、整面中心发白或密集渐变表现所有材质。
- 晶体先画晶面与切面，再沿晶棱安排高光；金属先确定边缘、接缝与有方向的连续反射，避免无目的的灰白散点把表面画成砂石或水泥。不同金属可以粗糙或哑光，不统一套亮铬效果；砂石控制细碎纹理的反差，防止远看变成棋盘或条纹。
- 类别色与材料明暗分别承担任务。先查看同一资源家族，保留已有颜色映射；若一类原本以蓝色识别，简化纹理时仍需保留足够的蓝色面积和对比。tint 决定类别色时沿用该机制，不能把整套压成近似的灰色后只在放大图中保留微小色差。
- 发光材质仍需保留形体和局部层次。贴图颜色、方块照明、着色器泛光是不同机制，预览不额外加模糊或光晕掩盖问题。
- 规则形状按所选镜像或旋转构造母版。16×16 局部画布的中心在 (7.5, 7.5)，放入图集后坐标随偏移变化；细节修改后按各部件的轴线、中心和对应关系复核。

成套或程序化材质可以采用 [结构场、蒙版和颜色映射](upstream-workflows.md#material-maker结构控制细节颜色映射控制家族) 方法，按共同参数控制细节的位置和尺度。图层/颜色角色便于保留用户认可的结构与类别映射；RGB 通道量化、随机噪声和平滑缩图都不能代替原生像素设计。

## 平铺和方块各面的验收

1. **原尺寸**：在实际像素尺寸下确认材质可辨认。放大时漂亮、缩回去只剩噪点的细节需要简化。
2. **最近邻放大**：检查轴线、色簇、意外透明像素、断裂和笔误。不用平滑缩放掩盖像素问题。
3. **至少 3×3 平铺**：查看接缝、重复大斑、连续条带、棋盘感和边框效应；不要在拼接线处画辅助线遮住问题。图集先按实际 UV 裁出正在使用的面，不能把含端盖、侧面和空白的整张 atlas 重复排列后声称侧面通过。
4. **实际方向**：模型若会旋转，额外排一组混合 0°/90°/180°/270° 的预览。柱体检查纵向连续性；不同面按模型 UV 的真实方向检查边与角，必要时画展开图或方块预览。
5. **修改后的复核**：查看重新导出的 PNG，与原版本及相邻类别并排看原尺寸和实际使用方向。对称、边缘数值只能确认指定约束，不能代替审美判断；平铺图也不能证明游戏内光照效果。

相对边缘逐像素相同是某些规则材质方便采用的设计约束，**不是无缝纹理的数学必要条件**。自然噪声可以在接缝处有正常的相邻像素差；应比较接缝两边的变化与纹理内部变化，并结合平铺图判断。不要机械复制整圈边框，制造新的双宽线或网格感。

端面和侧面使用不同图案时，先确认它们是否应该连成同一纹理。需要连续的晶棱或边框，应按方向比较对应边；不需要连续的切面可保持合理的材质分界，不强求所有边颜色相同。

## 可重复的检查工具

软件公开 `preview` 命令使用软件自带的图像处理能力，读取原生 PNG，输出 JSON，并可生成“原尺寸 + 最近邻放大 + 3×3 平铺”预览。可选新旧对照、局部区域和色簇检查；它不修改输入纹理，也不自动镜像或修补图片。

同一实现也可通过 `pixelforge preview PNG --output 预览.png` 调用；批次预演见 [事务与预览](transactions-review.md)，完整制作与交付按 [方块流程](workflows/block.md) 或 [纹理替换流程](workflows/replace-texture.md)。

在 Windows 上，例如：

```powershell
python <skill-base-dir>/scripts/pixforge_client.py preview crystal_end.png --expect-size 16 16 --opaque --symmetry d4 --tile --preview crystal_end-review.png
```

- `--symmetry none|lr|ud|both|diagonal|antidiagonal|rotate90|rotate180|d4`：默认不强制对称；在整图或所选局部区域中检查镜像、90°/180°旋转或复合关系。`rotate90` 只要求旋转，`d4` 还要求左右与上下镜像。两个斜向选项、`rotate90` 和 `d4` 要求被检查区域为正方形；`rotate180` 允许长方形。轴线与坐标见 [对称范围与变换](symmetry.md)。
- `--symmetry-space rgba|alpha|silhouette`：默认比较最终 RGBA；`alpha` 严格比较透明度数值，`silhouette` 比较指定阈值下的可见轮廓，两者都不能证明内部结构对称。结构层或语义掩膜可单独导出后作为输入检查。
- `--alpha-cutoff N`：`silhouette` 和可见范围报告采用 `alpha > N`，默认 0、范围 0..254；不改变 RGBA/alpha 比较、色簇、PNG 或预览，不冒充渲染器的 cutout 设置。`--binary-alpha` 仅在资源明确要求纯硬边透明时限制 alpha 为 0/255；默认允许半透明。
- `--region X Y W H`：只检查与预览指定部件或 UV 区域，坐标须在输入范围内；垂直动画先分帧，再在每帧中取该区域。尺寸、透明度、对称、色簇和平铺约束均应用于所选区域。不同部件可分别运行不同规则，不能以一个裁片通过声称整图对称。
- `--clusters`：报告四邻接同色可见 RGBA 色簇、尺寸分布和孤立像素坐标；透明像素不计入，半透明像素计入。斜向线、高光和颗粒可能合法地产生孤立像素，数量不是噪点或美观结论。`--max-isolated-pixels N` 仅在设计明确限定时启用，并自动开启色簇报告；默认没有上限。
- `--tile`：报告两个方向的边缘匹配和接缝差值，并在指定预览时加入 3×3 平铺。
- `--match-edges`：仅在设计明确要求相对边缘完全一致时启用；不会因为使用 `--tile` 自动启用。
- `--expect-size 宽 高`、`--opaque`：按目标资源声明被检查区域或每帧的尺寸与不透明要求。透明精灵不用 `--opaque`。
- `--compare 原版本.png`：静态图预览加入原版本的原尺寸、放大和可选平铺面板；选择区域时对两个版本取相同区域。仅在被检查尺寸相同时报告逐像素差异，不缩放原图来凑相同尺寸；该选项不与分帧检查组合。
- `--palette colors.json`：JSON 为非空数组，如 `["#25364a", "#657f9b", "#a9c5dc", "#657f9b80"]`。精确检查可见 RGBA，包括 alpha；全透明隐藏 RGB 不判错。静态图、所选区域和每帧都可使用，不自动量化或改色。未声明时允许项目需要的颜色，不将少色设为所有材质的硬约束。
- `--preserve-mask protect.png --compare before.png`：静态图修改范围验收。蒙版与两个版本须具有相同完整源尺寸，alpha 仅 0/255，至少保护一像素；255 对应的最终 RGBA 必须相同，0 允许修改。这个检查始终覆盖完整源图，`--region` 不会隐藏区域外的保护像素差异。它是导出后的核对，不是绘制时 alpha lock，不自动修复或移动像素。
- `--preview 路径`、`--scale 6`：预览输出路径与最近邻放大倍数；预览及动画派生图不能覆盖输入或原版本。输入必须是原生纹理，不把已经放大的展示图当作生产 PNG 检查。
- `--report full.json`：完整报告写入 JSON 文件，终端返回通过/失败和检查范围摘要；所有硬约束和帧仍检查。输入、预览、帧表和报告不能互相覆盖。未传此参数时保持完整 stdout JSON。
- `--backgrounds checker light dark`：按需在棋盘、浅色和深色背景上对照；默认只有棋盘。`--display-size W H` 加入指定绘制尺寸的最近邻预览，不替代目标渲染器实际过滤与光照检查。

JSON 包含透明度、可见包围盒/覆盖率、对称像素对应率和指定约束的失败项；开启平铺时还包含接缝与内部的平均 RGBA 差值。包围盒使用所选区域的局部坐标，边界为左/上包含、右/下不包含；接触边缘不自动判错。完全透明像素的隐藏 RGB 不参与比较。返回码 `0` 表示声明的约束通过，`1` 表示不符合这些约束，`2` 表示参数或文件问题；报告列出已声明的约束，没有约束时 0 只表示分析成功。输入须为单帧 PNG 或显式分帧的条带；APNG 会被拒绝，避免仅检查首帧。**没有“美观分数”**：即使返回 `0`，也要打开预览，检查过强的重复、单调和材质辨识度。

原生 PNG 放目标资源目录；`.px`、检查图和报告按项目约定存放。生产导出固定原生大小，预览另存；交付说明已经完成的视觉检查和仍需在游戏内验证的部分。

草稿阶段的选项选择、已有环境复用和成套图片合并运行见 [运行效率](performance.md)。简单改动不反复生成全部背景/状态的巨幅图，完整适用验收在代表样和交付阶段完成。
