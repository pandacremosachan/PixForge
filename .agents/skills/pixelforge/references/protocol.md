# PixForge 像素协议 v1

本文件定义 `.px` 绘图语法；完整制作流程见 SKILL.md 的任务表。共享工作台用专用接口创建/打开工程，通过 `session edit` / MCP `draw` 执行 `palette/grid/rle/patch/rect/set/read` 等绘图批次，再通过预览、保存与正式导出接口交付。共享批次不允许 `new/load/render/save/undo/redo`，不使用离线脚本绕过当前作品的历史或确认。

## 运行方式

```bash
python <skill-base-dir>/scripts/pixforge_client.py run script.px -o preview.png -S 8
```

上面是用户明确要求离线批处理或维护旧脚本时的兼容入口；完整离线脚本可以包含 new/render/save 等命令，不连接共享 runtime。普通工作台任务使用 [操作约定](operations.md) 中的 CLI 或 MCP；不假定当前 harness 已注册 MCP，也不要求使用特定厂商的工具前缀。

`run --atomic` 整批提交，`run --dry-run` 预演，`preview` 查看素材；旧 `.px` 语法保持兼容。批次修改与预览见 [事务与预览](transactions-review.md)。

离线生产纹理使用 `render asset.png 1` 保持原生分辨率，`-S 8` 的放大结果另存为预览；共享工程使用正式 export。可平铺材质另读 [材质设计与验收](textures.md)，本协议只定义绘图操作，不保证图像质量。

## 命令一览

| 命令 | 说明 |
|---|---|
| `new W H` | 新建画布（≤4096²），重置为单层 `main`，清空调色板/撤销 |
| `layer add\|use\|show\|hide\|remove NAME` / `layer list` | 图层（≤16），`add` 后自动激活；`list` 标 `*` 为当前层 |
| `mirror on\|off` | 对称模式：每次绘制额外贴一份水平镜像副本（轴=画布垂直中线） |
| `palette A=#rrggbbaa B=#rrggbb` | 字符→颜色。支持 `#rgb/#rgba/#rrggbb/#rrggbbaa`；alpha `ff`=不透明 `00`=全透明。`.` 恒为全透明，不可定义；**数字不能作调色板字符**（RLE 冲突） |
| `grid X Y` + 行负载 | 每字符=1 像素。负载行宽必须一致 |
| `rle X Y` + 行负载 | 游程编码：`4H2.6H` = `HHHH..HHHHHH`。计数可省略（默认 1）。行解码长度必须一致 |
| `patch X Y W H` + 行负载 | 原生 RGBA 网格：每行 W 个空格分隔的 `rrggbbaa` 单元，`.`=全透明。不经调色板，直接决定每点 RGB+α |
| `set X Y #rrggbbaa` | 单像素 |
| `rect X0 Y0 X1 Y1 #rrggbbaa` | 实心矩形（含端点，自动裁剪） |
| `clear X0 Y0 X1 Y1` | 擦除为全透明 |
| `read X Y W H [raw]` | **读回**（见下） |
| `render PATH [SCALE]` | 合成所有可见层，最近邻放大存 PNG |
| `save PATH` / `load PATH` | 会话 JSON（图层+调色板+镜像状态） |
| `undo` / `redo` | 快照式撤销（≤50 步），覆盖所有绘制与图层操作 |
| `info` | 画布尺寸/镜像/图层/调色板 |
| `stats [X Y W H]` | 区域颜色直方图 top16 |

## 负载规则（grid / rle / patch）

命令行的**下一行起**为负载，直到：空行、`#` 注释行、或下一条命令行。示例：

```
palette G=#2ecc71ff D=#27ae60ff
grid 4 4
GGGG
GDDG
GDDG
GGGG

rle 4 8
8G
2G4D2G
```

⚠️ **写入是替换语义**：负载里的每个像素（包括 `.` 全透明）都会**覆盖**画布上已有的像素。在已有画作上叠画小元素时，负载里不要用 `.` 占位——把每行裁剪到实际有内容的范围，分成多个 `grid` 小块分别定位，否则会把下面的画打成透明洞。

## 镜像语义

- 网格类（grid/rle/patch）：贴到 (X,Y) 后，再贴一份**水平翻转**副本到 (W−X−w, Y)。即：只画左半边，右半边自动对称。
- set/rect：坐标按 x → W−1−x 镜像。
- 翻转副本超出画布的部分自动裁剪。
- 此开关只实现左右镜像。上下镜像需按逆序行构造；四向对称还要求四分之一母版关于对角线一致，并验证完整图的 90° 旋转。
- 镜像副本写入仍是替换：母版与副本跨中轴重叠时，后写入的部分会覆盖前者，不会自动计算平均或保证对称。优先画不重叠的半边，或确保重叠部分本身满足对应关系；局部和其他轴线见 [对称范围与变换](symmetry.md)。
- 偶数尺寸的对称轴位于中间两个像素之间（如 16×16 的 x=7.5）；不要凭目测把中轴放在第 8 列像素上。

## 读回（反馈闭环）

`read X Y W H` 输出**可直接回贴执行的脚本片段**（自包含调色板定义）：

```
# read (4,4) 8x4, 3 colors
palette G=#2ecc71ff D=#27ae60ff
grid 4 4
GGGGGGGG
GDDDDDDG
...
```

`read raw` 输出 `patch` 片段（逐像素 `rrggbbaa`，用于精确核对）。约定：

- 读的是**合成后**画面（所有可见层叠加）；透明像素合成后显示为 `00000000`。
- 合成读回可在空白画布复现或作为明确的扁平化数据使用；回贴到已有半透明前景层后会再次与背景合成，不保证保持原结果。写入裁片时也要注意 `.` 替换语义。
- `read` 会为区域里的新颜色自动分配调色板字符（跳过已用字符），并永久加入调色板，保证多次 read 字符稳定。
- 区域颜色超过普通字符读回上限、剩余字符不足，或生成行与命令/注释语法冲突时，普通 `read` 自动返回精确 `patch` 片段；也可直接指定 `read raw`。这只是序列化选择，不是设计调色板的固定色数要求。

## 错误风格

所有错误带行号与绝对坐标，例如：

```
line 5 [grid]: payload row 2 col 7 (canvas 11,9): char 'Z' is not defined; palette has: . G D
```

修正对应坐标后重发即可。旧 CLI 默认失败前的命令可能已生效；事务模式整批回退。MCP 的 `draw` 使用原子事务并返回图像，`validate` 只预演；错误以 `isError` 和包含 `error/code` 的结构返回，不会中断会话。旧逐命令语义仅留在显式低层 CLI，不作为共享会话的另一条写入路径。

## 给 AI 的绘制建议

1. **先骨架后细节**：按设计需要构造大形，只有当前画布轴线符合目标时才用 `mirror on`；再 `read` 检查轮廓。按部件的实际镜像/旋转关系补细节，不把开关状态当作对称保证。
2. **token 效率**：平坦区域用 `rle`；逐像素精确控制（如渐变、噪点）用 `patch`；整体重画某层可 `clear` 后重铺。
3. **自查习惯**：每画完一个部件就 `read` 对应区域，确认坐标没有漂移；最终 `render` 输出 PNG 供视觉检查。
4. 调色板字符建议用有含义的字母（`S`=skin、`C`=cloth），`read` 返回的片段可原样粘贴继续编辑。

手写 `grid` 行若以 `#` 开头或恰好等于命令名，会被当作注释/命令；换用无歧义字符或 `patch`。命令文件的路径参数按空白分词，不支持含空格的路径引号；需要这样的输出路径时用 CLI 的 `-o "路径含空格.png"` 或 `-s "会话路径.json"`，渲染倍数另用 `-S`。最终查看原生导出，并遵循 [设计与验收](design-review.md)。

共享会话的绘图批次只修改当前工程；新建、打开、保存、撤销与导出使用专用接口。离线 run 仍支持完整 .px 协议。
