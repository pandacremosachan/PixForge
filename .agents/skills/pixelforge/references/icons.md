# 小尺寸图标与工具

适用于物品、升级卡、工具、槽位图标和独立像素图标。先确认原生尺寸、界面实际绘制尺寸和相邻素材；本文不指定统一分辨率、边框或调色板。

风格提取、配色主次、边缘节奏和背景检查见 [设计决策与视觉验收](design-review.md)。小图标同时核对负形、触点间距、无意相切和轮廓转折，不只统计孤立色点。

## 先画能读懂的大形

先用轮廓、主部件和留白建立构图，在原尺寸下查看，再添加接缝、触点和高光。每个细节应帮助辨认结构、材料、用途或等级。若缩回原尺寸后只能看到碎点，合并成连续色簇或删除；不要靠增加装饰像素填满空白。

机械卡片可以按外壳、主芯片、触点组织层次，但这只是构图选择。主部件的面积、间距和对比要形成清楚的主次；边框、芯片、引脚若都以相同强度闪烁，图标会碎。金属感来自边缘、接缝和有方向的连续反射，不靠散布灰白点；简化时保留这些材料线索。

成套图标先建立共同的轮廓、结构尺度、光源与触点位置，再通过有意义的部件变化和类别色区分。并排看全部成员：等级须容易分辨，每张也须独立可读。共同布局不等于所有物品套同一模板；类别色遵循项目已有约定及用户认可的颜色。

## 轴线、结构和光照分别检查

按 [对称范围与变换](symmetry.md) 分别确定主部件、边框、触点和工具头的关系。它们可以采用不同的局部轴线、斜轴、中心或旋转规则；不要求整个图标遵循同一个镜像。触点数量相等也不能证明位置正确。

例如 16 像素宽的局部部件中心是 7.5，触点位置 `4,6,9,11` 关于它对称；部件放进更大的画布后，轴线须随位置平移。定向高光可让对称结构上的颜色不同，分别检查轮廓、内部结构与最终 RGBA。`mirror on` 只认当前画布中线，完成组合和细节后按各部件的约束检查最终导出。

## 色簇与有意保留的单像素

在最近邻放大图中检查同色像素的连续组织，再回到原尺寸判断可读性。无目的、无结构关联的小亮点容易形成杂点；把它们合并成边缘、连续触点或明确的主部件。

眼睛、指示灯、尖角高光、抖动和自然颗粒可以有意使用单像素。检查工具的“孤立像素”指没有上下左右同色邻居的可见 RGBA 像素，斜向连续线也可能被计入；它提供坐标和结构证据，不自动判定噪点。仅在设计已明确不需要这些单像素时声明上限，不能把零孤立像素或固定色数设为所有像素画的验收标准。

## 对照与验收

在草稿目录保留原生版本，用同一背景和相同最近邻倍数并排比较；原尺寸图也必须展示。看完整图标、家族成员和实际界面缩放，检查主次、留白、材料辨识度与类别区分，不能只看放大后的单张卡片。

透明图结合浅色与深色背景查看，必要时按真实绘制尺寸检查轮廓和细线。包围盒可辅助核对基线、裁切和可见重心，但不能代替视觉平衡判断；成套或动画素材沿用约定基线，不逐张按包围盒自动居中。

通过软件公开接口检查，例如：

```powershell
python <skill-base-dir>/scripts/pixforge_client.py preview card.png --symmetry lr --clusters --compare card-before.png --preview card-review.png
python <skill-base-dir>/scripts/pixforge_client.py preview diagonal-tool.png --symmetry antidiagonal --symmetry-space silhouette --backgrounds checker light dark --preview tool-review.png
```

第一条报告同色连通簇、孤立像素位置和前后像素变化，不自动要求零孤立像素。若这张卡明确要求没有孤立色点，再加 `--max-isolated-pixels 0`。第二条只检查工具在可见性阈值下的轮廓；内部结构仍须核对，成品颜色要求对称时使用默认 `rgba`，透明度分布本身要求对称时使用 `alpha`。这些命令检查已导出的 PNG，不替代 PixForge 绘制与 `read` 读回。

发现问题后主动修改并重新看最终 PNG；不为每一步草稿新增审批。沿用用户已确认的部分，交付具体对照与实际检查范围。游戏启动、存档和部署遵循任务项目规则及已有授权。
