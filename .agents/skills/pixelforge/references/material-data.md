# LabPBR data maps through the public application

For normal/AO/height, smoothness/F0/metal, porosity/SSS or emission work, confirm `minecraft-material/v1` through `project info` before selecting operations. Use the application's public data-map operations for storage, editing, shader-target checks and export; do not edit project/checkpoint JSON directly.

Use `minecraft material-inspect` for the current raw planes, pixel values, histograms, decoded meanings and target issues. `resource="namespace:path"` resolves source `_n`/`_s` with the software's priority and provenance. Inspecting is read only. For native-window review, call `workbench editor --editor-kind material; operation="open"`, read its `status`, and use the returned field/action identifiers; the default action only inspects.

Read the current project with `project state`, then apply `minecraft material-configure --settings {"profile":"labpbr-1.3"}`. Use `minecraft material-import --role "normal" or "specular",path FILE` for exact-size 8-bit PNG; optional channel copies the mask's R plane into one channel. Use `minecraft material-edit --role,channel,operations` for atomic batches such as `[{"rect":[2,3,1,1],"value":0}]`. Every write submits current expected_document_id/expected_revision. Native editor operations use the status field/action identifiers.

Data alpha is not opacity. Normal A is height; specular A 0..254 is emission and **255 means ignored/zero**, not maximum emission. Normal RG encodes DirectX XY with reconstructed Z; B is AO. Specular R is perceptual smoothness; G switches between F0, named/reserved metal IDs and albedo-metal fallback; B switches between porosity and SSS. View all eight planes and the software's decoded report. Never route a data map through color-layer compositing, sRGB correction, resizing or ordinary paint operations.

Bind the consuming project's actual shader name/version, loader/version, required options and true/false/null feature declarations. Supply an authorized local ZIP/directory and expected SHA when available. Treat unknown as unknown. The bundled owned Probe 1.0.0 example pins OptiFine I6 / Forge 47.2.18 and explicitly excludes height/POM, named metals, porosity and SSS. Do not generalize that loader combination to other Forge builds or install it automatically. Shader source inspection, offline GPU decoding and a declaration do not establish game behavior.

Use normal `minecraft check`, inspect all eight data planes and retain real user consent for the currently shown content before guarded Minecraft export. The software pairs data sidecars with the same albedo binding, frame layout and animation indices. Cross-frame category interpolation, impossible normals, unsupported used features, source hash changes and conflicting global LabPBR declarations can block export. Save editable drafts while resolving these issues. A content or dependency change requires a fresh check; no separate workflow review receipt is used.

Data projects and recovery history require format v4, introduced in software 2.7; check format compatibility before switching application connections. Game comparison with data maps requires observed active shader/hash/options/reload context from the opt-in Forge fixture; report offline and actual game validation separately. For exact byte semantics and supported target boundaries, read `MINECRAFT_MATERIAL_DATA.md` beside the resolved application and its returned capability/report data.
